# BUG-009: Select popup 与 trigger 视觉脱节、Flag 行溢出 dialog

## 描述

BUG-008 的部署版本（commit d94aef5）上线后，用户截图反馈两处仍然破：

1. Channel selector 点开后，popup 在 trigger 中段向上扩展，盖住 "Channel" label；popup 与 trigger 视觉风格也完全脱节（trigger 是 `rounded-pill` 大椭圆 + `text-base`，popup 容器是 `rounded-md` + 内部 item 用 `rounded-sm` + `text-sm`），看上去像两个独立浮动元素而不是一组件。popup 宽度也不严格匹配 trigger（用 `min-width: var(--anchor-width)` 允许更宽）。
2. Upload version dialog 里 Publish / Critical / Intermediate 三个 FlagCheckbox 横排塞在 `grid sm:grid-cols-2` 的最后一个 cell（半宽）里，三个 label + checkbox + gap 总宽超出 cell，Intermediate 直接溢出 dialog 右边界。

验收标准：

1. Select popup 严格贴在 trigger 下方（不再向上覆盖 label），popup 宽度严格等于 trigger 宽度，item 字号和 padding 与 trigger 形成层级关系。
2. Publish / Critical / Intermediate 三个 flag 在所有视口下都不溢出 dialog；窄屏可换行兜底。
3. typecheck / test / lint / e2e 全部通过、无新增 warning。

## 进行时描述

完成 SelectContent / SelectItem / index.css `.select-popup-width` 与 upload-version-dialog flag 行布局的视觉/布局收敛。

## 笔记

- 2026-05-02 11:25：直接进入实施。

  根因：
  - Popup 上移：Base UI `<Select.Positioner>` 默认 `alignItemWithTrigger: true`（macOS-native 行为：把当前选中 / 高亮 item 中心对齐 trigger 中心），导致 popup 顶部在 trigger 上方、覆盖 label。
  - Popup 宽度：`.select-popup-width` 用 `min-width: var(--anchor-width)`，popup 内容 padding 一旦超过 anchor 宽度就会撑开。
  - 视觉脱节：trigger 是 `rounded-pill` + `text-base` + `h-11`；popup item 是 `rounded-sm` + `text-sm` + `px-sm py-xs`；字号、节奏、padding 都不在同一套语言里。
  - Flag 溢出：dialog `max-w-lg`（512px）→ grid 半 cell 约 226px；三个 flag (Publish 84 + Critical 104 + Intermediate 134 + 2×gap 32) ≈ 354px > 226px，必然溢出。

  修复：
  - `select.tsx`：`<BaseSelect.Positioner>` 显式 `alignItemWithTrigger={false}`，让 popup 走默认 `side="bottom"` 贴 trigger 下方。
  - `select.tsx`：`SelectItem` 改 `text-base px-3 py-2`，与 trigger 字号协调，padding 节奏从极紧收到中等。
  - `index.css`：`.select-popup-width` `min-width` → `width`，popup 严格匹配 anchor 宽。
  - `upload-version-dialog.tsx`：flag 容器移出 `grid sm:grid-cols-2`，作为独立一行 `flex flex-wrap gap-x-4 gap-y-2`，拿到 dialog 全宽 + 窄屏自动换行兜底。

  验证：`bun run typecheck`（pass）、`bun run test` 12/12（pass）、`bun run lint`（0 errors，46 既存 warnings、无新增）、`bun run test:e2e` 80/80（pass）。
