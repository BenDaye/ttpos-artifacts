# ENH-019 给 Caddy splice 脚本补漂移门（--check）

- **status**: completed
- **priority**: P1
- **createdAt**: 2026-08-12
- **related**: REFACTOR-007（/dl 迁 Caddy）、PLAN-037（Caddy 边界）、BUG-017/PLAN-039（resolve=artifact-latest）、REFACTOR-010

## 描述

`deploy/scripts/migrate-caddy-shortlinks.sh` 的 dry-run 会打印 `result: candidate differs from target`，但 `cmp` 的结果只决定打印哪一句，随后**无条件 `exit 0`**。也就是说它看起来能检测主机 Caddyfile 漂移，实际上永远汇报成功——挂进 cron 或 CI 配 `set -e` 会得到永久绿灯，比没有检测更糟。

`deploy/Caddyfile` 是 `/dl` 短链契约的唯一事实源，而生产/预发生效的是主机上 splice 出来的副本，仓库侧的 `caddy_config_test.go` 守不到。缺一个能真正失败的门。

2026-08-12 实测佐证：生产 `/opt/caddy/Caddyfile` 与仓库派生候选**只差两行中文注释**（BUG-017 的 prod rollout 是手工改 rewrite 行完成的，没走脚本），功能行逐字相同。因此逐字节比对的门会从第一天起就是红的，很快被忽略。

## 修改

新增 `--check` 漂移门：

- 只比对**功能行**，跳过整行注释与空行；理由是注释不影响 Caddy 行为、且各主机合理不同（见上）。行内尾随注释不做特殊处理，按差异计。
- 有差异 → 打印功能行 unified diff + `exit 2`；无差异 → `exit 0`。
- 与 `--apply` 互斥（`die`），永不写文件。
- **不改动既有行为**：不带 `--check` 时 dry-run 仍 `exit 0`，因为迁移场景下「有差异」本来就是预期，把它当失败会破坏正常流程。
- usage 补 `--check` 说明与一个 cron/CI 示例。

## 验收

六个用例逐个单独跑、看真实退出码（不经管道）：

| 用例 | 期望 | 实际 |
|------|------|------|
| staging Caddyfile 完全一致 | OK / 0 | ✅ EXIT=0 |
| prod Caddyfile 只差两行注释 | OK / 0 | ✅ EXIT=0 |
| 删掉 `&resolve=artifact-latest` | FAILED / 2 | ✅ EXIT=2，diff 指出该行 |
| 改掉一条 alias 的 arch | FAILED / 2 | ✅ EXIT=2，diff 指出该行 |
| `--check --apply` 同时给 | die / 1 | ✅ EXIT=1 |
| 不带 `--check`、有差异 | 旧行为 / 0 | ✅ EXIT=0 |

`bash -n` 通过（EXIT=0）。本机无 shellcheck，未跑。

对照样本来自 aissh 只读拉取的两台真实主机 Caddyfile（`sha256sum` + `base64` 传输，远端与本地 sha256 双向核对）。

## 后续

- 门只覆盖「配置有没有漂」，覆盖不到「回退语义是否真的会触发」；后者需要常驻哨兵 app + 端到端探针，另行立项。
