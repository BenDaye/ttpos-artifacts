# ENH-014 完整打通 Statistics(遥测)功能

## 背景与根因

Statistics 页面"完全没看到实际效果"。基于 vm-node02(staging)运行态实测定位:

- 前端完整接好(路由 `/statistics`、侧栏导航、`StatisticsPage`、筛选栏、i18n en/zh `telemetry.json`)。
- 后端已启用:staging `ENABLE_TELEMETRY=true`,`/telemetry` 不会 403。
- **真正原因:Redis 整库为空(DBSIZE=0,`stats:*` 零键),遥测从未被记录过一次。**

记录链路缺陷:

1. 记录只在 `/checkVersion`(`latest.go` 的 `trackClientTelemetry`),且要求客户端发送 `X-Device-ID` 头;头为空就 early-return,连请求数都不记。经确认 **TTPOS 更新客户端目前不发送该头**。
2. staging `PERFORMANCE_MODE=true`:`FindLatestVersion` 在缓存命中时 early-return(latest.go:159)早于记录调用(:177)——响应被缓存后,后续相同 checkVersion 全部不记录。
3. 前端有 "Today" 按钮,但后端 `GetTelemetry` 只认 `week`/`month`,选 Today 返回 400。
4. 前端未区分"遥测被禁用(403)"与普通错误。

## 决策(已获批)

- 范围:全量修复 + staging 演示。
- 客户端不发送 `X-Device-ID`,故服务端在缺头时用 `client IP + User-Agent` 派生稳定假名标识,使所有图表(而非仅请求数)都能从 checkVersion 已带参数填充。
- 无设备 ID 时也计入流量(由 fallback 标识自然满足:total_requests/每日趋势/分布均累计;unique_clients = 不同 IP+UA 组合的近似)。

## 实现

### server(Go)

- `latest.go`
  - 新增 `resolveDeviceID(c)`:优先 `X-Device-ID`,缺失则 `anon-<sha256(ip|ua)[:8]>`;不存储原始 IP/UA。
  - 缓存命中分支也调用 `logStatsToRedis`,`hasUpdate` 取自缓存响应的 `update_available`(新增 `cachedUpdateAvailable`)。
  - miss 路径设备 ID 改用 `resolveDeviceID`。
- `telemetry.go`
  - 抽出纯函数 `resolveTelemetryDateRange(range,date,now)`,新增 `today` 单日支持;非法 range 仍 400。
  - `mergeResults` 用 `asFloat` 等安全断言,避免 Lua 返回缺键时 panic→500。
- 单测(miniredis + 纯函数):`resolveDeviceID`、`resolveTelemetryDateRange`、`cachedUpdateAvailable`、`trackClientTelemetry` 写入键校验。

### dashboard-next(前端)

- `statistics-page.tsx`:错误态按 `HttpError.status` 分支——403 显示"遥测未启用"(无重试)、503 显示"遥测后端不可用"(可重试)、其余沿用通用 `ErrorState`。
- `telemetry.json`(en/zh):新增 `errors.disabled` / `errors.unavailable`。

## 验证

- server:`go build ./...`、`go vet ./...`、`go test ./server/handler/info/...`。
- 前端:`bun run typecheck`、`bun run lint`、`bun run test`。
- staging 演示:部署 api 后,合成 `/checkVersion`(带与不带 `X-Device-ID`,新参数)→ 复核 `stats:*` 键出现 → 确认页面有数据。

## 备注

- 前端 dashboard 镜像仅在打 `dashboard-next-v*` tag 时打包;本次前端为健壮性改动(遥测已启用时不可见),数据可见性仅依赖 server 镜像更新。
- 客户端是否原生发送 `X-Device-ID` 属另一仓库范畴;当前 fallback 已使生产无需等客户端改造即可出数据。
- 缓存命中记录路径(PERFORMANCE_MODE)依赖 `FindLatestVersion`,本地无 mongo 无法做端到端单测,**该路径仅由 staging 部署演示验证**;单测覆盖 `resolveDeviceID`/`resolveTelemetryDateRange`/`cachedUpdateAvailable`/`trackClientTelemetry` 等可隔离单元。
- 安全评审判定 staging 不阻断,但 `/checkVersion` 公开端点有 HIGH 级硬化项(限流、SetTrustedProxies、HMAC 假名),**生产暴露前必做**,见 [SEC-008](SEC-008.md)。
