# ENH-012: dashboard-next 自身版本号管理

- **status**: completed
- **priority**: P2
- **owner**: ben
- **createdAt**: 2026-06-02
- **completedAt**: 2026-06-02
- **related**: -

## 描述

dashboard-next 的 `package.json` 一直有 `version` 字段，但从未在 UI 任何地方展示，仓库也没有 git tag 或发布流程。`features/apps` 里的 "version" 概念是管理 FaynoSync 分发的**应用**版本，与 Dashboard 自身无关。本任务让 dashboard-next **自身**支持版本号管理，分两部分：

1. **展示自身版本**：在侧边栏底部常驻展示 Dashboard 自己的版本号，hover 显示完整的版本 · git commit · 构建时间。
2. **发布流程**：建立 bump 版本号、归档 changelog、打 tag 的发布脚本。

版本来源采用**构建时注入**。

## 方案

### 构建时注入

- `apps/web/vite.config.ts` 新增 `define`，注入三个全局常量：
  - `__APP_VERSION__`：取 `apps/web/package.json` 的 `version`（优先 CI 的 `APP_VERSION` env），作为单一事实来源。
  - `__GIT_COMMIT__`：git short hash。优先取 CI 经 build-arg 注入的 `GIT_COMMIT`，本地构建回退到本机 `git rev-parse --short HEAD`，失败回退 `unknown`。
  - `__BUILD_TIME__`：构建时刻 ISO 字符串（可经 `BUILD_TIME` env 覆盖）。
- `apps/web/src/vite-env.d.ts`：声明上述全局常量类型。
- `apps/web/src/shared/lib/app-version.ts`：集中读取注入值（`buildInfo`），并提供纯函数 `formatVersionLabel` / `formatBuildTooltip`（入参驱动，便于测试）。

### 关键约束：Docker 与 CI 接线

- `.git` 不在 Docker 构建上下文内，`oven/bun:alpine` 镜像也无 `git`，因此**只有 git commit 必须经 build-arg 注入**；`APP_VERSION`（vite 读 package.json）与 `BUILD_TIME`（容器内生成）天然可用。
- `dashboard-next/Dockerfile`：在依赖安装层**之后**、构建之前新增 `ARG GIT_COMMIT` + `ENV`，避免每次构建使依赖缓存层失效。
- `.github/workflows/build-dashboard-next.yaml`：build job 已有的 `git_info` 步骤算出 `COMMIT_SHA`，新增 `build-args: GIT_COMMIT=...` 传给 `build-push-action`。build job 工作目录为仓库根，故未在 CI 里读 package.json（交给容器内 vite），规避路径坑。

### UI 展示

- `apps/web/src/shared/components/app-version-badge.tsx`：侧边栏底部常驻版本徽标。**刻意做成非交互元素**（纯 `div`，无 role/link/button），避免干扰 e2e 中依赖 `getByRole('link'/'button', { name })` 的导航与登出断言；折叠态居中显示，hover 经 `title` 显示完整信息。
- `app-shell.tsx`：登出按钮下方挂载 `<AppVersionBadge />`。
- `common.json`（en/zh）：新增 `version.aria`。文案保持品牌中立（不出现 TTPOS）。

### 发布流程

- `dashboard-next/CHANGELOG.md`：Keep a Changelog + 语义化版本格式，含 `[Unreleased]` 段。与按日期记录的 `docs/changelog.md`（产品级）用途不同、并行维护。
- `dashboard-next/scripts/bump-version.ts`：以 `apps/web/package.json` 为单一事实来源计算新版本号，同步写回根与 web 两处 `package.json`，归档 CHANGELOG 的 Unreleased 段，并**打印**建议的 git commit / tag 命令（不自动提交、不自动打标签，遵循 AGENTS.md）。
- 根 `package.json`：新增 `version:patch|minor|major` 脚本。

### 发布触发（打包锁 tag）

- `.github/workflows/build-dashboard-next.yaml`：Docker 打包&推镜像改为**仅在打 `dashboard-next-v*` tag 时执行**，分支推送只跑质量门。
  - `on.push` 新增 `tags: ["dashboard-next-v*"]`；依据 GitHub 官方行为「**paths 对 tag 推送不评估**」，tag 必触发、且现有 `paths` 对分支推送的约束不变（actions/runner#3933 佐证）。`tags` 过滤同时挡掉 server 等其它 tag 的误触发。
  - `build` job 加 `if: startsWith(github.ref, 'refs/tags/dashboard-next-v')`，把打包锁定在 tag；手动 `workflow_dispatch` 选 tag ref 也能打包，选分支则只验证。
  - Docker 镜像 tag 改为 `type=match,pattern=dashboard-next-v(.*),group=1`（从 tag 提取版本号如 `0.2.0`）+ `latest` + commit `sha`。
  - 与 `bump-version.ts` 的打 tag 命名 `dashboard-next-v<version>` 闭环：bump → commit → 打 tag → CI 仅此时打包推镜像。
- **连带影响**：dashboard-next 部署（vm-node02 的 push→CI→pull `:latest`）从此**改为发版触发**——`:latest` 只在打 release tag 时更新。

## 验证

- `bun run typecheck`、`bun run lint`、`bun run test`：通过。
- `bun run build`：通过，构建产物中含注入的版本元数据。
- bump 脚本：`bun run scripts/bump-version.ts` dry 验证版本计算与 changelog 归档（验证后还原）。
- e2e：版本徽标为非交互元素，未触碰既有 sidebar `getByRole` 断言。
- workflow：`build-dashboard-next.yaml` YAML 语法校验通过；触发与 `build.if` gating 逻辑经核对（paths-不评估-tag 行为以 GitHub 官方文档与 actions/runner#3933 为据）。GitHub Actions 无法本地实跑，需首次打 tag 时在远端确认镜像 tag 与触发。
