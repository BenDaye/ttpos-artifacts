# BUG-012: 完善 latest 路径式下载入口投产缺口

- **status**: completed
- **priority**: P1
- **owner**: codex
- **createdAt**: 2026-05-08
- **completedAt**: 2026-05-08
- **related**: FEAT-001, PLAN-020

## 描述

FEAT-001 已新增 `/latest/:owner/:app_name/:channel/:platform/:arch[:package]` 路径式下载入口，但投产审计发现仍有缺口：路径路由缺少直接回归测试，app/channel 未命中时会返回 500 而不是 404，Redis latest cache key 未隔离 owner，外部文档与 CMS 发布 workflow 仍主要使用 `/apps/latest` query 入口。

## 范围

- 修正 `/apps/latest` 与 `/latest/...` 在 app/channel 不存在时的 404 语义。
- 将 latest/checkVersion cache key 纳入 owner 维度，并同步缓存失效 pattern。
- 为 `/latest/...` 增补 302、JSON fallback、404 和 cache key 直接测试。
- 将 CMS 下载页发布 workflow 的 FaynoSync 查询切到 `/latest/...` 路径入口。
- 补充 server API 文档与 changelog。

## 验收标准

1. `/latest/:owner/:app_name/:channel/:platform/:arch/:package` 命中单一 artifact 时返回 302 Location。
2. `/latest/:owner/:app_name/:channel/:platform/:arch` 命中多个 package 时返回 JSON。
3. app/channel 未命中时返回 404 而不是 500。
4. Redis cache key 包含 owner，缓存失效能覆盖新 key 形态。
5. CMS workflow 查询使用路径式 latest URL，并正确 URL encode path segment。
6. `go test ./...`、`go build ./...` 或可用等价 gate 通过；若本地环境缺少 Go，需要记录验证缺口。

## 进行时描述
