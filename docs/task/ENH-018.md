# ENH-018 Docker 构建改用 turbo prune 剪枝上下文

- **status**: pending
- **priority**: P3
- **owner**: 未认领
- **createdAt**: 2026-07-04
- **related**: PLAN-036, REFACTOR-009, ENH-017

## 描述

web/mcp 镜像目前靠手工维护的 manifest COPY 清单（`COPY apps/*/package.json` 等）+ 根 `.dockerignore` 白名单让 `bun install --frozen-lockfile` 通过。这套手工账在 PLAN-036 评审中已炸过一次（MAJOR-1：新增 workspace 成员 @ttpos/server 后漏 COPY 即构建失败），且每新增成员都要记得同步三处（bun.lock ⟺ Dockerfile COPY ⟺ dockerignore）。

改用 `turbo prune @ttpos/web --docker`：生成只含目标包及其依赖的剪枝目录（`out/json` = 全部所需 manifest，`out/full` = 源码子集），Dockerfile 两段 COPY 即可，新增成员自动纳入，白名单 .dockerignore 可大幅简化。

## 约束

- **构建路径已实证，重写必须重新实证**：PLAN-036 的三镜像构建在 staging 实建通过（REFACTOR-009 批注），本任务改动 Dockerfile 后必须重新在可跑 docker 的环境实建 web/mcp 两镜像并对比产物行为（VITE_API_URL 占位符替换、GIT_COMMIT 注入、nginx/entrypoint 拷贝层）。
- 验证 `turbo prune` 对 bun workspace + bun.lock 的支持成熟度（turbo 对 bun lockfile 的 prune 支持晚于 pnpm/yarn，需按当时 turbo 版本实测 lock 剪枝正确性；不成熟则搁置本任务）。
- server 镜像（context=apps/server，纯 Go）不涉及，不动。
- CI build job 的 context/file 参数与 gha 缓存层随 Dockerfile 结构同步调整。

## 验收

- web/mcp Dockerfile 不再有逐成员手工 COPY 清单；新增 workspace 成员无需改 Dockerfile（用一个临时成员实测）。
- 两镜像实建通过 + 运行时行为回归（entrypoint 替换、版本号注入、/healthz）。
- 根 .dockerignore 简化后 build context 体积不回退。

## 起步交接（2026-07-05 状态）

**当前 Docker 现状（要改的东西）**：
- `apps/web/Dockerfile`：手工 COPY 清单——`COPY package.json bun.lock` + `COPY packages/config|shared/package.json` + `COPY apps/web|mcp|server/package.json`（含为 frozen-lockfile 补的 apps/server manifest）→ `bun install --frozen-lockfile` → `COPY tsconfig.json eslint.config.js` + `COPY packages packages` + `COPY apps apps` → build。context=仓库根，`GIT_COMMIT` build-arg，运行期 nginx + `docker-entrypoint.sh` 注入 `VITE_API_URL` 占位符。
- `apps/mcp/Dockerfile`：同款手工 manifest 清单（含 apps/server），context=根，运行 `bun run apps/mcp/src/index.ts`，健康 `/healthz`。
- 根 `.dockerignore`：白名单式（`*` 全排 + `!package.json !bun.lock !tsconfig.json !eslint.config.js !packages !apps` + `apps/server/*` + `!apps/server/package.json` + `**/node_modules` `**/dist` `**/.turbo` 等）。
- `apps/server/Dockerfile`：纯 Go，context=`apps/server`，**不涉及本任务，别动**。

**目标机制**：`turbo prune @ttpos/web --docker` 生成 `out/json`（所需 manifest 子集）+ `out/full`（源码子集）+ 剪枝后的 lockfile → Dockerfile 两段 COPY（先 out/json 装依赖、再 out/full 拷源码），删掉逐成员手工 COPY 与大部分白名单 .dockerignore。新增 workspace 成员自动纳入，不用再改 Dockerfile（这正是根治 PLAN-036 踩过的「漏 COPY apps/server 导致 frozen-lockfile 炸」那类坑）。

**Gotcha（务必注意）**：
1. **turbo prune 对 bun.lock 的成熟度要先验**：turbo@2.10.3 已装；prune 对 bun lockfile 的支持晚于 pnpm/yarn/npm。先 `turbo prune @ttpos/web --docker` 看 `out/` 里生成的 lockfile 是否有效、`bun install --frozen-lockfile` 在 out/ 里能否过。**不成熟就搁置本任务**，别硬上。
2. **Docker 本机跑不了（LXC）**：本会话所有镜像 build 都在 staging(vm-node02) 代跑（`aissh` server_id 见记忆 `aissh-vm-access`）。验证必须上 staging，本地只能生成 out/ 目录检查。
3. **必须重验运行期行为**：web 的 `VITE_API_URL` 占位符替换 + `GIT_COMMIT` 注入 + nginx serving；mcp 的 `/healthz` + `MCP_TRANSPORT`。改 Dockerfile 后要在 staging 实建两镜像并跑起来验这些，不能只看 build 成功。
4. **CI build job 的 `context:`/`file:` 参数随 Dockerfile 结构调整**（build-dashboard.yaml、build-mcp.yaml 的 build job）。
5. **server 镜像不碰**（纯 Go、独立 context）。

**建议第一步**：分支上 `bunx turbo prune @ttpos/web --docker`，检查 `out/json`/`out/full`/剪枝 lockfile 是否合理、能否 frozen install。若 bun 剪枝可用，再改 web Dockerfile → 上 staging 实建 + 运行期回归；mcp 同法。若 bun 剪枝不成熟，把结论记进本任务并搁置。

## 先验结论（2026-07-05）：bun.lock 剪枝成熟，任务可做

本地（turbo 2.10.3 + bun 1.3.13）实测 `turbo prune --docker`，四项全过：

1. **依赖解析正确**：`@ttpos/web` 剪出 config+shared+web；`@ttpos/mcp` 只剪出 config+mcp（mcp 不依赖 shared）——比现 Dockerfile 手工清单还精确（现清单把 server manifest 也塞进来了）。
2. **剪枝 lockfile 真剪且可用**：`json/bun.lock` 中 apps/mcp、apps/server workspace 条目已移除；在 `json/` 内 `bun install --frozen-lockfile` 通过（web 1502 包 / mcp 1174 包）。
3. **两段 COPY 可构建**：模拟 Dockerfile 模式（先 json 装依赖、full 覆盖后 build），`@ttpos/web` 构建成功，dist 产物中 `__VITE_API_URL_PLACEHOLDER__` 占位符存在。
4. **根配置文件缺失但无害**：`full/` 不含根 `tsconfig.json`/`eslint.config.js`（现 Dockerfile 单独 COPY 的两个文件），但 build 不需要它们——tsconfig extends 链走 `@ttpos/config` 包，不引用根文件。改写 Dockerfile 时这两行 COPY 可直接删。

剩余工作：改写 web/mcp Dockerfile 为 prune 两段式（builder 内先 `turbo prune` 或 CI 预剪）、简化 `.dockerignore`、同步 CI build job 的 context/file 参数，然后上 staging(vm-node02) 实建两镜像 + 运行期回归（entrypoint 替换、GIT_COMMIT 注入、mcp /healthz）。
