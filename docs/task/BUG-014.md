# BUG-014: 修复 Dashboard Next 移动端工具栏控件堆积

- **status**: completed
- **priority**: P1
- **owner**: codex
- **createdAt**: 2026-05-09 11:05
- **completedAt**: 2026-05-09 11:14
- **related**: PLAN-030

## 描述

移动端 Dashboard Next 的搜索框、过滤按钮组、视图切换按钮和主操作按钮在窄屏下仍会挤在同一块区域，虽然多数页面已避免 document 级横向溢出，但局部工具栏的可读性和触达性不足。目标是让移动端工具区形成清晰分层：搜索占据独立输入行，过滤/切换类控件使用可横向浏览的工具条，主操作按钮在窄屏下拥有稳定可点击空间。

## 范围

- 收敛 Applications、App detail versions、Statistics 的工具区响应式布局。
- 复用既有 Button、ToggleGroup、Popover、Input，不新增视觉 token 或硬编码颜色。
- 增加聚焦 responsive e2e，覆盖窄屏下搜索框、过滤按钮组和主按钮不互相挤压。
- 保持现有 API、query key、路由、board 高度链和数据交互行为不变。

## 验收标准

1. 320px / 375px 宽度下，应用列表搜索框、App detail version filter、Statistics filter controls 没有互相压缩成不可读区域。
2. 搜索框在移动端独占一行；过滤按钮和 ToggleGroup 不把搜索框压窄。
3. PageHeader 主操作按钮在移动端不与切换器/返回按钮堆叠到同一窄列中。
4. 过滤按钮数量较多时不产生 document 横向滚动，局部横向浏览区域可用。
5. `dashboard-next` 聚焦 typecheck、lint、responsive e2e 或等价验证通过。
