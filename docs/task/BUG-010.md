# BUG-010: Upload version 不应允许编辑 App name；移除孤悬的全局上传入口

- **status**: completed
- **priority**: P1
- **owner**: codex
- **createdAt**: 2026-05-02 11:40
- **completedAt**: 2026-05-02 11:40
- **related**: PLAN-017

## 描述

用户复核 BUG-009 部署后指出：Upload new version 对话框里的 App name 字段是普通可编辑 Input，用户可以把已经从某个 app 触发的上传改成另一个 app name，造成版本绑错 app（甚至绑到不存在的 app name）。

调查发现该字段可编辑的根因是 applications-page 顶部有一个孤悬的"Upload version"全局按钮 — 它弹出 dialog 时不传 app context，所以字段必须可编辑让用户手输。但 applications page 上的 card / list / board view 都没有 per-app upload 入口，唯一真正合理的 upload 路径是先进入某个 app 的 detail page。这个全局按钮纯属设计错位，让用户被迫手输 app 名字、错字风险高。

验收标准：

1. UploadVersionDialog 的 App name 字段强制 readonly + disabled，从父组件 prop 注入；prop 从 optional `defaultAppName` 改为必传 `appName`。
2. applications-page 顶部的全局 "Upload version" 按钮（含相关 state 与 dialog 实例）整体移除；upload 流程只能从 app detail page 触发。
3. typecheck / test / lint / e2e 全部通过、无新增 warning；删除依赖被移除按钮的 applications.spec.ts upload e2e 用例。

## 进行时描述

## 笔记

- 2026-05-02 11:40：根因定位 + 修复一并完成。

  根因：
  - `UploadVersionDialog` 接收 optional `defaultAppName?: string`；applications-page 不传，导致字段必须可编辑让用户填，留下"绑错 app"漏洞。
  - applications-page 顶部 "Upload version" 全局按钮没有 app context，但全 app 列表上又没有 per-app upload 入口（card / list / board view 全无）；用户在那个按钮上点击只是被迫进入"输入 app 名字"的尴尬流程，唯一真正可行的上传路径是 detail page。

  修复：
  - `upload-version-dialog.tsx`：
    - `Props.defaultAppName?: string` → `Props.appName: string`（必传）
    - `useForm.defaultValues.app_name = appName`，并加 `useEffect` 把 prop 同步进 form state，避免 reset 后丢失 app 上下文
    - JSX 改成 `<Input value={appName} disabled readOnly />`；label 加 hint "Locked to this app" / "锁定到当前应用"（新增 i18n key `apps.upload_dialog.app_name_locked`）
  - `app-detail-page.tsx:193`：调用从 `defaultAppName={appName}` 改为 `appName={appName}`。
  - `applications-page.tsx`：移除顶部 "Upload version" 按钮、`uploading` state、`UploadVersionDialog` 实例，以及对应的 `Upload`、`UploadVersionDialog` import；upload 流程收敛为"从 detail page 进入"。
  - `apps.json`（en / zh）：新增 `app_name_locked` 词条。
  - `e2e/applications.spec.ts`：删除依赖全局按钮的 `upload version button opens upload dialog` 用例（同等覆盖已在 `app-detail.spec.ts` 的 `upload version button opens upload dialog with app pre-filled` 中保留）。

  验证：`bun run typecheck`（pass）、`bun run test` 12/12（pass）、`bun run lint`（0 errors，46 既存 warnings、无新增）、`bun run test:e2e` 79/79（pass，因移除 1 个不再适用的用例少 1 项）。
