# BUG-013: 修复 Dashboard Next App board 双层纵向滚动

- **status**: completed
- **priority**: P1
- **owner**: codex
- **createdAt**: 2026-05-09
- **completedAt**: 2026-05-09
- **related**: PLAN-027

## 描述

Dashboard Next 的 Applications board 视图在版本数量较多时会同时出现页面级纵向滚动和 column 内部纵向滚动。目标是让 board 自动填充当前 screen 的剩余高度，只保留 column 内部滚动，避免用户在同一方向上需要滚动两层容器。

## 范围

- 收敛 Applications page 在 board 布局下的纵向 flex 约束。
- 让 App board 外层占满 header/search 之后的可用高度。
- 让每个 board column 继承 board 高度，并由 column 内的 version 列表承担纵向滚动。
- 增加针对 board 纵向滚动归属的回归验证。

## 验收标准

1. `/applications` 选择 board 视图后，版本数量较多时 document/page 不产生额外纵向滚动。
2. board column 的 version 列表可以独立纵向滚动。
3. board 横向滚动仍保留在 board 外层，不引入 document 横向溢出。
4. card/list 视图现有布局不回退。
5. `dashboard-next` 聚焦 typecheck、lint、e2e 或等价验证通过。

## 进行时描述

已完成 Applications board 高度链收敛：board 填充可用 viewport 高度，版本列表纵向滚动限制在 column 内。

## 依赖

- **blocked by**: 无
- **blocks**: Dashboard Next App board 长版本列表可用性

## 笔记

- 2026-05-09：调查定位到 `ApplicationsPage`、`AppBoardView` 与 `index.css` 的 board 高度约束。当前 `.app-board-scroll-area` 使用固定 `100vh` 推导的 `max-height`，但 page/main/board 外层没有统一的纵向 flex 高度链，导致 column 滚动之外仍可能触发页面级滚动。
- 2026-05-09：用户批准 PLAN-027，认领任务开始实现。
- 2026-05-09：实现完成。`ApplicationsPage` 仅在 board 布局下启用固定 viewport 可用高度与 flex 高度链；`AppBoardView`/`BoardColumn` 改为 `h-full min-h-0`；移除 `.app-board-scroll-area` 固定 `max-height`，由 column 内部 `overflow-y-auto` 承担版本列表滚动。
- 2026-05-09：验证通过：`bun install --frozen-lockfile`、`bun run typecheck`、`bun run lint`（0 errors，保留既有 warning）、`bun run build`、`bunx playwright install chromium`、`bun run test:e2e -- responsive-layout.spec.ts`（28/28）、`git diff --check`。真实 preview 可打开，但未配置登录态/后端 mock 时会重定向到登录页。
- 2026-05-09：根据复核反馈微调 column 内部结构：在 `.app-board-scroll-area` 外增加 `py-2` 高度 wrapper，滚动元素自身保留 `h-full overflow-y-auto px-2`，让上下视觉留白固定在滚动区域边界。
