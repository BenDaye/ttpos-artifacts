# BUG-017 /dl 短链在部分平台发版时对缺失平台 404

- **status**: deployed（已合并 PR #33 / commit a01f4db；server-v1.0.1 部署 vm-node02 + prod，staging 三态验证通过，prod 零回归上线）
- **priority**: P1
- **createdAt**: 2026-07-06
- **plan**: PLAN-039
- **related**: REFACTOR-007（/dl 迁 Caddy）、ENH-008、PLAN-036

## 描述

生产发 2.25.6 时只发 macOS/Windows，Android 短链 `/dl/shop.apk` 404。根因：`/dl` 经 Caddy rewrite 到 `/apps/latest`，其语义是「取 app+channel 最新 published 版本，再在该版本内过滤 platform/arch/package 制品」——缺失平台在选版阶段没有发言权，只能事后过滤为空 → 404，不回退到上一个有制品的版本。

判定为缺陷（设计缺口）：短链是官网/二维码的常青入口，业界（update.electronjs.org、Sparkle per-OS feed、electron-builder per-platform latest.yml）均为 per-platform latest 语义；「有意不让某平台下载」应通过 unpublish 表达，不靠制品缺失。

## 修复

`/apps/latest` 新增显式 opt-in `resolve=artifact-latest`（platform/arch/package 三参齐全时生效）：版本选举改为「包含匹配制品的最新 published 版本」。Caddy /dl rewrite 独占开启该参数；默认行为逐字不变（保护 MCP 等透传调用方）。

- `apps/server/mongod/check.go`：`FetchLatestVersionOfAppForTarget`（初始 `$match` 内 `artifacts.$elemMatch`：platform/arch ObjectID + `normalizePackage`(库内带点小写形态) + link 非空，四条件同子文档；复用 `sortVersionPipeline`/`getBasePipeline`）；`ErrTargetNotFound` 哨兵。
- `apps/server/server/handler/info/latest.go`：窄接口 `latestTargetRepository` 调用点断言；`CreateCacheKey` 增加 `resolve` 维度（两种语义不共享缓存键）。
- `deploy/Caddyfile` rewrite 追加 `&resolve=artifact-latest`；`caddy_config_test.go` 契约同步。

双向兼容：参数未上=旧行为；参数上了旧镜像=未知参数被忽略=旧行为。回滚 = revert 单 commit 或 Caddy 去参数，任一侧单独回滚安全。

## 验收

1. staging：最新 published 版本缺 apk、前序含 apk → `/dl/<alias>.apk` 302 指向前序版本制品。
2. 最新版含 dmg → `/dl/<alias>.dmg` 302 指向最新版（不误回退）。
3. 无任何含 apk 的 published 版本 → 404、`no-store`。
4. `/apps/latest` 无 `resolve` 参数行为逐字不变（单测回归断言 + staging 抽查）。
