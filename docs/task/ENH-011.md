# ENH-011: version 列表同版本号内按 channel 列表顺序二级排序

- **status**: completed
- **priority**: P2
- **owner**: ben
- **createdAt**: 2026-06-02
- **completedAt**: 2026-06-02
- **related**: ENH-010

## 描述

app-detail-page 的 version 列表里,同一个 version 号发布到多个 channel 时会出现多条记录（每条带一个 `Channel`）。此前这些同 version 记录的相对顺序完全由后端聚合管线决定：`getBasePipeline` 的 `$sort` 只有版本号四段（`major_v/minor_v/patch_v/build_v`）降序，**没有 channel 维度的 tiebreaker**，因此同 version 多 channel 之间的顺序 Mongo 不保证稳定；前端 `versions` useMemo 又只过滤、不重排,直接沿用后端顺序。结果是同 version 的多个 channel 排列没有规律。

本任务让同 version 号内的多 channel 记录**按 channel 列表所见的顺序**排列,与左侧 channel 列表（ENH-010 起支持拖拽自定义顺序）一致。

## 方案

**纯前端、零后端/契约改动**（方案 A，与用户确认）。

- 新增纯函数 `sortVersionsByChannel(versions, channelOrder)`（`version-ui.ts`）：
  - **主序**：每个 version 号在输入中首次出现的位置 —— 完整保留后端按版本号降序返回的块顺序,不打乱版本号排序。
  - **次序**：channel 在 channel 列表中的**位次**（`channelOrder`）升序,与左侧 channel 列表顺序一致。
  - **末序**：位次相同 / channel 不在列表中时,按 channel 名 `localeCompare` 稳定收敛。
  - 不修改入参,返回新数组。
- `app-detail-page.tsx`：接 `useChannelsQuery`,用其 `data` 的**数组下标**（而非 `c.Sort`）构建 `channel 名 -> 位次` 的 `Map`,在 `versions` useMemo 过滤之后调用排序。

> **为什么位次取数组下标而非 `c.Sort`**：channel 列表后端按 `{sort:1,_id:1}` 返回,`useChannelsQuery().data` 已是该顺序的数组。直接取下标作位次,在两种状态下都与 channel 列表所见一致：
> - 未拖拽（`Sort` 全为 `0`,Go `int` 零值）：下标 = `_id` 创建序 = channel 列表顺序。若改用 `c.Sort`,此时全相等会退化为字母序,反而与 channel 列表（创建序）不一致。
> - 拖拽后（`Sort` dense `0..N`）：下标 = `Sort` 序 = channel 列表顺序。

> **为什么纯前端足够**：版本列表是单 app 范围、后端分页 `limit 50`,且同 version 的多 channel 记录在版本号排序后天然相邻,被分页切断概率低。前端在当前页内对同 version 块重排即可满足诉求,无需改动被 `check.go` 四处复用的核心聚合管线。

## 范围

- `dashboard-next/apps/web/src/features/apps/components/version-ui.ts`：新增 `sortVersionsByChannel` 纯函数。
- `dashboard-next/apps/web/src/features/apps/components/version-ui.test.ts`（新增）：5 个单测覆盖位次排序、列表非字母序时跟随列表、块顺序保留、未知 channel fallback、不可变。
- `dashboard-next/apps/web/src/features/apps/components/app-detail-page.tsx`：接线 `useChannelsQuery` + `channelOrder` map,排序接入 `versions` useMemo。

## 验收标准

1. 同 version 多 channel 按 channel 列表顺序排列,与左侧 channel 列表（含拖拽后的自定义序）一致。
2. channel 列表为非字母序（如创建序 prod/test/dev）时,version 子排序跟随列表序而非字母序。
3. 不打乱后端版本号降序的块顺序（只在同 version 块内重排）。
4. channel 不在列表中时稳定按 channel 名收敛,不报错;零后端、API、共享类型、契约改动。

## 已知边界（非阻塞）

- 后端分页 `limit 50`：同 version 记录若被分页切到不同页,只能在当前页内重排（罕见,单 app 版本通常远少于 50）。
- channel 列表数据未就绪（`useChannelsQuery` pending）时 `channelOrder` 为空,所有 channel 走名次兜底;数据到达后 useMemo 重算。channel 列表与 filter bar 共用同一 query,通常已缓存。
