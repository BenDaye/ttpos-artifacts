# SEC-008 遥测公开端点的生产硬化门(ENH-014 后续)

ENH-014 打通了遥测记录链路:`/checkVersion`(公开、未认证)在缺 `X-Device-ID` 时用 `client IP + User-Agent` 派生假名标识并写入 Redis。安全评审(opus)判定 **staging 不阻断**(vm-node02 无生产暴露),但 **任何公开/生产暴露前必须先完成以下项**。结论等级:HIGH。

## MUST(生产暴露前)

1. **`/checkVersion` 速率限制(HIGH)**
   - 现状:`/login`、`/signup` 有 `RateLimitMiddleware`,但 `/checkVersion` 没有。ENH-014 去掉了"空设备 ID 早返"这道天然限流,并新增缓存命中也记录 → 攻击者轮换 `X-Device-ID` 可廉价膨胀 Redis 集合(`unique_clients`/`channels:*`/`platforms:*` 等,30 天 TTL)并撑大内存;管理员打开 dashboard 时 Lua 对超大集合做 `SMEMBERS` 自我 DoS。
   - 修法:`utils.NewIPRateLimiter` + `RateLimitMiddleware` 挂到 `/checkVersion`,限额需兼顾 NAT 后大量真实客户端共享出口 IP。**依赖第 2 项先修**,否则所有客户端会并到代理 IP 同一桶。

2. **`router.SetTrustedProxies(...)`(HIGH)**
   - 现状:`server.go` 用 `gin.Default()` 未设可信代理,gin 默认信任所有代理 → `c.ClientIP()` 采信客户端伪造的 `X-Forwarded-For`。连带影响:`/login`、`/signup` 限流按可伪造 IP 分桶,可被轮换 XFF 绕过(比遥测更严重)。
   - 修法:`SetTrustedProxies` 仅信任 Caddy 所在 docker 子网(按 `caddy-net` 实际网段填写并验证),Caddyfile 配 `header_up X-Forwarded-For {remote_host}`。

3. **假名标识改 HMAC + 采集声明(MEDIUM,生产升 MEDIUM-HIGH)**
   - 现状:`anon-<sha256(ip|ua)[:8]>` 是可逆假名——输入熵低(IPv4≈32bit、UA 近常量),持哈希者可离线暴力反推 IP。瓶颈是熵不是字节数,故"加长截断"不是修法。
   - 修法:改 `hmac.New(sha256.New, key)`,key 经 env(如 `TELEMETRY_HMAC_KEY`)注入、勿硬编码;并在隐私/API 文档声明"缺 X-Device-ID 时基于 IP+UA 生成假名标识、保留 30 天、仅内部分析可见"。

## SHOULD(建议同批)

4. **Lua `KEYS` → `SCAN`(MEDIUM)**:`telemetry.lua` 的 `KEYS` 全库阻塞,与集合膨胀叠加放大停顿;参照 `tuf/bootstrap/bootstrap.go` 的 `Scan`。唯一计数可评估 HLL(`PFADD`/`PFCOUNT`),但与现有"按维度过滤求交"算法不兼容,需配套调整。
5. **`owner` 加正则校验(LOW)**:`validate.go` 中 `owner` 未校验(其它字段有正则且禁含冒号)。当前被 `apps_meta` 存在性检查兜底不可利用,仍建议纵深防御加 `^[a-zA-Z0-9\-]+$`。
6. **第三方依赖升级(与本功能无关,另排期)**:`govulncheck` 报 `golang.org/x/net@v0.47.0`(→v0.55.0)、`go-jose/v4@v4.1.3`(→v4.1.4);另有 12 项 Go 1.25.5 标准库项,用更新的 1.25.x 补丁版重编镜像即可消除。

## 备注

- 这些项部分为既有问题(2、4、5、6),ENH-014 主要放大了 1、3 的影响面。
- vm-node02 为 staging,上述风险在受控环境可接受;部署演示见 ENH-014。
