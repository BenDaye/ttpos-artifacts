## 描述

对 dashboard-next 前端做一次以用户体验为核心的交互细节巡检，聚焦弹窗、布局、选中高亮等细节。由四条只读审计赛道（弹层 / 布局与三态 / 选中高亮与交互态 / 表单反馈与可访问性）并行扫出问题，按「明确低风险修复」与「需用户拍板」分流：前者直接实施，后者仅就一个真正动 `DESIGN.md` 原则的配色决策征询用户。

## 唯一的产品决策：危险/错误语义色

`--destructive` 此前映射到品牌蓝（`--apple-primary`），导致删除确认按钮与普通主操作按钮**完全同色**、表单校验错误文字也是蓝色，用户无法辨识「危险/错误」。该问题还 gate 了三项视觉修复（输入框错误红边框、错误提示文字、删除按钮辨识度）。

**用户拍板：引入语义警示色（status color，非第二品牌强调色）。** `DESIGN.md` 的 Known Gaps 自述「Form validation and error states were not surfaced」，即从未覆盖错误/危险态，故新增一个经 `@theme` 接入的警示色不违反「交互元素单蓝」原则——所有正常交互元素仍是单蓝。

## 方案与改动

### 共享基础层（手术式改动 + 3 个新原语）

- `index.css`：新增固定调色板 `--apple-status-danger`(#C1121F) / `--apple-status-danger-on-dark`(#FF6961)，light/dark 的 `--destructive` 改引用它；`@theme` 暴露 `--color-apple-status-danger*`。`--primary` 保持单蓝不动。
- `ui/button.tsx`：`destructive` 变体从「与 default 同款蓝」改为 `bg-destructive text-destructive-foreground hover:bg-destructive/90`（真红）。
- `ui/input.tsx`、`ui/textarea.tsx`：新增 `aria-[invalid=true]:border-destructive aria-[invalid=true]:focus-visible:ring-destructive`（错误态红边框/红聚焦环）。注意本项目 Tailwind v4 **未内置 `aria-invalid` variant**，必须用 arbitrary variant `aria-[invalid=true]:`（这是选择器变体，非 `DESIGN.md` 所禁的 arbitrary *value*）。
- `ui/dialog.tsx`：`DialogHeader` 统一加 `pr-xl` 给右上角关闭按钮让位（修长标题被 X 压住）；关闭按钮 `aria-label` 改走 i18n `common:actions.close`。
- `common/confirm-dialog.tsx`：描述改用 `DialogDescription`（补 `aria-describedby` 关联）；loading 期间锁关闭（`onOpenChange` 守卫）。
- `common/entity-form-dialog.tsx`：`DialogBody` 加 `dialog-scroll-area overflow-y-auto`（**修 P0：长表单弹窗内容溢出视口、顶部字段无法触达**，一处覆盖全部 10 个表单弹窗）；loading 期间锁关闭（一并防住 create-token 在请求中被关闭导致 token 悬空丢失）。
- `empty-state.tsx`：新增 `iconClassName` 支持。
- **新原语** `error-state.tsx`：基于 EmptyState 的统一错误态，固定告警图标（红）+ 重试按钮，使「加载失败」明确区别于「暂无数据」。
- **新原语** `ui/password-input.tsx`：复用 Input 全部样式（含 aria-invalid）+ 眼睛明文切换，正确转发 `aria-invalid`/`aria-describedby` 到内部 input。
- **新原语** `ui/tooltip.tsx`：基于 Base UI Tooltip 的组件化提示 + `SimpleTooltip` 便利封装（供后续把截断文本的原生 `title` 升级）。
- i18n：`common.json` 新增 `actions.retry`/`show_password`/`hide_password`、`states.error_title`/`error_description`（en/zh）。

### feature 层（按 feature 目录 + i18n 命名空间分三条互不重叠赛道并行实施）

- **apps**：错误态→ErrorState+重试（applications/app-detail）；加载骨架按 list/card/board 分支以消除切换抖动(CLS)；三视图可点卡片/行加 `active:bg-accent` 按下反馈（不用 scale，避免与拖拽 transform 冲突）；list-view 修正 ARIA 角色（`role="row"`→`role="button"` 对齐卡片视图，表头 `aria-hidden`）；看板被打开详情的版本卡加单蓝选中描边 + `aria-current`；删除死类名 `app-board-scroll-area`；截断 app 名补 `title`；upload-version 校验文案 i18n + changelog placeholder i18n + 首字段 autoFocus；version-detail 去掉与基元重复的 `pr-xl`。
- **settings**：错误态→ErrorState+重试（tokens/users）；tokens 空态补创建操作；`'no rights'` 硬编码→i18n；permission-matrix 的 `<summary>` 补 focus-visible 聚焦环；create-token 首字段 autoFocus；team-user/admin 密码字段→PasswordInput。
- **auth + 页面错误态**：sign-in/sign-up 校验文案 i18n + 密码字段→PasswordInput；platforms/channels/architectures/statistics 四页错误态→ErrorState+重试。

## Follow-up（本轮刻意延后，未做）

- **ToggleGroup 改用 Base UI composite 基座**：现 `ToggleGroupItem` 是手写 `<button>`，未注册为 composite item，方向键 roving-focus 失效、每个选项各自成 Tab 停靠点（违反「交互组件用成熟 headless」）。键盘仍可用（可 Tab + Enter 激活），非阻塞。改动涉及 shared 基座契约 + layout-switcher/telemetry-filter-bar 两处消费方受控化 + 键盘回归，属中等重构，单列后续批次。
- **add-artifact-dialog 首字段 autoFocus**：首字段是 `SelectField`，当前不转发 autoFocus 到 Base UI trigger；需扩展 SelectField 或接受无自动聚焦。
- **全站间距 token 口径统一**（旧页面 `p-4`/`gap-2`/`mb-4` → 语义 token）：大 churn、视觉回归面大、与「交互细节」主题不符，延后。
- **5 个 useState 表单弹窗迁 react-hook-form**：当前校验仅弹通用 toast、无内联字段错误；迁移工作量大，分批进行。
- **`app-version-badge.tsx` 的 `text-[11px]`**：唯一残留 arbitrary value（token 无 11px），需在 `text-micro`(10)/`text-xs`(12) 间做像素取舍。
- **截断文本 tooltip 升级**：本轮以原生 `title` 兜底，`SimpleTooltip` 原语已就位，可逐步替换。
- **看板 `.app-board-page` svh 高度减算**：审计疑似溢出/双滚动，需窄/宽屏实测后再定，未盲改。
