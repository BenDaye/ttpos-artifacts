# BUG-011: 移除 New app 表单残留的 Enable TUF metadata 入口

- **status**: completed
- **priority**: P1
- **owner**: codex
- **createdAt**: 2026-05-02 13:02
- **completedAt**: 2026-05-02 13:02
- **related**: PLAN-019

## 描述

用户复核 QUAL-003 部署后指出 New application 表单里仍有 "Enable TUF metadata" 复选框。AGENTS.md 明确"TUF 前端入口当前保持禁用"，但 `app-form-dialog.tsx` 有一个长期遗留的 TUF 启用 checkbox，用户勾选后会通过 `useCreateAppMutation` 把 `tuf: true` 提交给后端、激活 TUF 元数据生成路径——这就是 AGENTS.md 边界上"还活着的"前端入口。

之前几轮（BUG-008 / 009 / 010 / QUAL-003）都没覆盖这个 checkbox，因为它住在 `apps/components/` 而不是 `features/tuf/` 目录下，我每次扫"TUF 路径"都把它跳过了。

验收标准：

1. New app 表单不再向用户呈现 "Enable TUF metadata" 入口（checkbox + 相关 state + mutation 路径里的 `tuf` 字段全部移除）。
2. 不动 `useCreateAppMutation` / `appsApi.createApp` / `CreateAppPayload` 的契约（`tuf?: boolean` 仍在 API type 上，因为它属于后端契约的一部分；前端不传等于 undefined → 默认 false）。
3. 不动 i18n key `apps.form.tuf`（按 TUF off-limits 边界保留为孤儿词条；删 i18n 也是动 TUF 文案）。
4. 不动 `features/tuf/` 任何文件、不动 `settings.tuf.disabled_*` 文案（前者按 off-limits 边界，后者本就是"已禁用"提示符合现状）。
5. typecheck / test / lint / e2e 全部通过、无新增 warning。

## 进行时描述

完成 New app 表单 Enable TUF 入口移除，落实 AGENTS.md "TUF 前端入口禁用"边界。
