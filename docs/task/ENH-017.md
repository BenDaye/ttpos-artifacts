# ENH-017 CI 改用 turbo --affected 替代手写 paths 过滤

- **status**: pending
- **priority**: P3
- **owner**: 未认领
- **createdAt**: 2026-07-04
- **related**: PLAN-036, REFACTOR-009, ENH-018

## 描述

三个构建 workflow（build-dashboard/build-mcp/build-server）目前各自维护一长串 `on.push.paths` 过滤器来决定「改了什么才跑质量门」，且 `packages/**` 是粗暴全触发。改为质量门统一入口 `turbo run typecheck test build --affected`，由 turbo 按 git base + 依赖图自动计算受影响的包：改 `packages/shared` 自动带跑 web/mcp（手写 paths 做不到的传递依赖），文档-only 改动零任务。

## 约束

- **tag 门控逻辑必须逐字保留**：`web-v*`/`mcp-v*`/`server-v*` 触发 build job 的 if-gate、meta 提取与 paths 无关，不得被重构波及。
- `--affected` 需要 checkout 足够深度（`fetch-depth: 0` 或设 `TURBO_SCM_BASE`），PR 与 push 事件的 base 计算方式不同，需分别验证。
- server 质量门（go build/vet/单测）若并入 turbo 入口，CI runner 需 setup-go；评估是否保留独立 job 更简单。
- 迁移后用一次「只改 docs」「只改 shared」「只改 server」三种 PR 实测触发矩阵再合并。

## 验收

- 三 workflow 的 paths 清单删除或收缩到 workflow 自身文件；质量门由 `--affected` 驱动。
- 传递依赖触发实证：改 packages/shared 的 PR 带跑 web+mcp 质量门。
- tag 发版链路回归：打一个 tag 确认 build job 行为与 PLAN-036 现状一致。

## 起步交接（2026-07-05 状态）

**当前 CI 现状（要动的东西）**：
- `.github/workflows/build-dashboard.yaml`：`paths:` 一长串（apps/web/**、packages/**、根配置…），tag `web-v*`；质量门 `bunx turbo typecheck/test/build --filter=@ttpos/web`；已有 `actions/cache@v4` 缓存 `.turbo`（key `turbo-${os}-${sha}`，restore `turbo-${os}-`）。
- `build-mcp.yaml`：paths 较短（apps/mcp/**、packages/**、根配置），tag `mcp-v*`，同款 turbo 缓存 + `--filter=@ttpos/mcp`。
- `build-server.yaml`：paths `apps/server/**`，tag `server-v*`；**质量门是裸 go build/vet/test**（有自己的 setup-go，不走 turbo），无 .turbo 缓存。

**两个「层」别混淆**（这是本任务的核心）：
- `paths:`（workflow 触发层）决定 workflow **跑不跑**；`--affected`（turbo 任务层）决定哪些包的任务跑。要真正用上 --affected，通常做法：放宽/去掉 workflow 的 paths（让质量门 job 总是跑）→ 靠 `turbo run <task> --affected` 让它自动只跑受影响的包（改 packages/shared 会自动带 web+mcp）。手写 paths 的 `packages/**` 是「粗暴全触发」，做不到传递依赖精确性。

**Gotcha（务必注意）**：
1. **tag 门控与 paths 正交，绝不能碰**：build job 的 `if: startsWith(github.ref,'refs/tags/<x>-v')` + meta `type=match,pattern=<x>-v(.*)` + `flavor latest=false`。GitHub 对 **tag 推送本就忽略 paths**（workflow 注释已写明），所以 --affected 主要惠及分支/PR 推送。
2. **--affected 需要 git base 比对**：push 事件要 `fetch-depth: 0`（或设 `TURBO_SCM_BASE`/`TURBO_SCM_HEAD`）；PR 与 push 的 base 算法不同，分别验。
3. **server 并入 --affected 要 setup-go**：`@ttpos/server` 的 turbo 任务是 `go vet/test/build`（见 turbo.json，inputs 限 `**/*.go`），runner 需装 Go（当前 server job 已有 setup-go，若统一入口要保留）。
4. **turbo 已装 2.10.3、bun 1.3.13**；turbo.json 已定义 build/typecheck/test + @ttpos/server# 专属 inputs。

**本地验证**：`bun install` → `bun run lint` → `bunx turbo typecheck test build`（跑 server 任务需 `export PATH=$PATH:$HOME/.local/go/bin`，本机装了用户态 Go 1.25.5）→ `bun run test:e2e`（先 `bunx playwright install chromium`）。**Docker 相关本机跑不了（LXC），要 build 镜像得上 staging(vm-node02)。**

**建议第一步**：别一次改三个。先在分支上只改 `build-dashboard.yaml` 做原型——放宽 paths + 质量门改 `bunx turbo <task> --affected`（配 fetch-depth:0），用一个「只改 packages/shared」的 PR 验证是否自动带跑 @ttpos/web，跑通再推广到 mcp、再考虑 server（要 setup-go）。三种验证 PR：只改 docs / 改 packages/shared / 改 apps/server。
