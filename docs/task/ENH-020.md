# ENH-020 短链数据化：新增 app 后短链自动可用

- **status**: deployed（staging + prod 均已切换，15 条短链逐条零回归）
- **priority**: P1
- **createdAt**: 2026-08-12
- **plan**: PLAN-043
- **related**: REFACTOR-007（/dl 迁 Caddy，本任务就 /dl 部分反向）、BUG-017/PLAN-039、ENH-019

## 描述

新增一个 app 的下载短链，当前要改 3 个文件、发一次版、再登 2 台主机改反代配置并 reload。TTPOS 会继续加 app，这条路径必须能自助。

把短链从「反代配置里的一张表」改为「app 的一个属性」：app 表单里填一个短链名，短链自动可用，无需发版、无需登主机。不做独立的「短链管理」页面——目标是**不存在需要记住的运维步骤**，而不只是步骤更少。

前提：项目已定性为 TTPOS 专用发版应用，放弃平台化（本次会话决策）。

## 验收

1. 现有 15 条 URL 字节不变，切换前后 `Location` 逐条完全相同（切换前基线已于 2026-08-12 取到，全部指向 2.27.3）。
2. 后台新建 app 并填短链名后，不发版、不登主机，短链立即可用。
3. app 详情页能看到并复制该 app 的短链。
4. 大小写变体仍可用；未知短链名 400 + `no-store`；有效短链名无制品 404 + `no-store`；成功 302 缓存头在 origin 侧与今天一致。
5. `/apps/latest` 行为逐字不变。
6. Caddy 不再包含 `/dl` map，契约测试改为断言其不存在。

## 非目标

- 不做 iOS 短链（无需求）。
- 短链继续只服务 prod 渠道，渠道不进 URL。
- 不碰 TUF、不做自定义域名、不做多客户能力。
