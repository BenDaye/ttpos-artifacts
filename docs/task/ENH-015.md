# ENH-015 把服务封装成 MCP Server(只读外置包装器)

## 背景与目标

把 FaynoSync 后端服务(`server/`,版本/应用/渠道/平台/架构/遥测 REST API)封装成一个
**MCP(Model Context Protocol)server**,让支持 MCP 的 AI agent(Claude Desktop / Claude Code 等)
能以标准工具调用方式查询发布平台的数据。

本期范围 **只读先行**:只暴露查询类工具,零破坏性操作;create/update/delete/upload 留待后续按需扩展。

## 决策(已确认)

- **架构:外置 TS 包装器**。在现有 Bun workspace 新建独立包,通过 HTTP 调 FaynoSync REST API。
  - 理由:`server/` 是仓库跟踪的上游开源项目(`module faynoSync`,`github.com/ku9nov/faynoSync`)。
    把 MCP 内嵌进 Go 二进制会和上游**永久分叉**、后续合并上游成本高;外置包装器可零侵入升级上游。
- **范围:只读**。查询类工具优先落地。
- **传输:stdio**(本地接入 agent),不做远程 HTTP/SSE。
- **鉴权:环境变量**。支持 `API_TOKEN` 直传,或 `API_USERNAME`+`API_PASSWORD` 登录换 JWT 并缓存、401 自动刷新。

## 硬边界(贯穿始终)

- **Brand-neutral**:MCP server 名、工具名/描述、README、manifest 一律中性(发布/制品平台口径),
  不出现 TTPOS 等内部品牌。`server` 的 McpServer name 用中性名(如 `release-registry`)。
- **不暴露 TUF 端点**:`/tuf/*` 一律不做工具。
- **不暴露写/破坏性端点**:upload、各类 delete、create/update、token/user 管理、admin 全部不在本期范围。

## 端点与鉴权事实(已核对源码)

`server/server/server.go` 在 `router.Use(authMiddleware)` 之后注册的端点都需要 JWT:

| 工具 | HTTP | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `health_check` | GET `/health` | 公开 | 服务健康(mongo/redis ping) |
| `latest_version` | GET `/apps/latest` | 公开 | 取应用最新版本(纯读) |
| `list_apps` | GET `/app/list` | JWT | 应用列表,参数 `page`/`limit` |
| `search_versions` | GET `/search` | JWT | 版本检索,`app_name` 必填,可选 `channel`/`platform`/`arch`/`published`/`critical`/`page`/`limit` |
| `list_channels` | GET `/channel/list` | JWT | 渠道列表 |
| `list_platforms` | GET `/platform/list` | JWT | 平台列表 |
| `list_architectures` | GET `/arch/list` | JWT | 架构列表 |
| `get_telemetry` | GET `/telemetry` | JWT + 实例开启遥测 | 聚合统计,参数 `apps`/`channels`/`platforms`/`architectures`/`range`(today/week/month)/`date` |
| `whoami` | GET `/whoami` | JWT | 当前用户与权限(便于校验凭据) |

- **刻意排除 `/checkVersion`**:它会写入遥测(`stats:*`),属副作用,违背"只读";改用纯读的 `/apps/latest`。
- `get_telemetry` 在实例未开启遥测时返回 403 —— 工具需把它映射成清晰的"遥测未启用"提示而非裸报错。

## 技术选型(已核对 npm/context7)

- `@modelcontextprotocol/sdk@^1.29.0`(稳定版;`McpServer` + `registerTool` + `StdioServerTransport`,支持 zod v4)。
  - 注:`@modelcontextprotocol/server` 目前仅 `2.0.0-alpha`,不采用。
- `zod@^4.4.3`(与 web 现有 `zod@^4` 对齐,用于工具 inputSchema)。
- 运行时:Bun(workspace 原生执行 TS);typecheck 用 `tsc --noEmit`;测试用 vitest(与 web 一致,自动并入 `bun --filter '*' test`)。
- 不复用 web 的 `shared/lib/http.ts`(它依赖 `localStorage`/`window`,仅浏览器可用);新写一个极薄的 fetch 客户端。
  实体类型(`AppSummary`/`AppVersion`/`Channel`/`Platform`/`Arch`)从 `@ttpos/shared` 复用。

## 风险与缺口

- 本环境无 docker/mongo,无法本地起完整 server;协议层用 mock fetch 单测覆盖,真实数据冒烟依赖 vm-node02。
- `@ttpos/shared` 实体字段命名(大驼峰 `ID`/`AppName`)与 REST 响应一致,直接透传即可;若个别端点字段有出入,以源码 handler 为准、在 `types.ts` 内对齐。

## 实现说明(已落地)

落地结构与 proposal 一致。关键实现点:

- `client.ts` 用 `redirect: 'manual'` 捕获 3xx,`latest_version` 返回 `{ redirect, status }` 而非下载二进制;
  login 模式登录后缓存 JWT,遇 401 清缓存并重登一次。
- 工具结果统一为 text content(`JSON.stringify`);`get_telemetry` 把 403 映射成
  "Telemetry is not enabled on this server instance." 并置 `isError`。
- 入口 `index.ts`:stdout 留给 MCP 协议,所有诊断走 stderr;配置非法即 stderr 报错 + exit 1。

### monorepo zod 对齐(必要的连带改动)

`@modelcontextprotocol/sdk@1.29` 解析到 `zod@4.4.3`,而 web 当时锁在 `zod@4.3.6`。zod v4 的
`$ZodType` 核心类型在 4.3.6↔4.4.3 间结构不同:**版本一旦发散**,hoisted 的 `@hookform/resolvers`
会按顶层 zod 解析类型,与 web 的 schema 版本对不上(`_zod.version.minor` `3` vs `4`),web typecheck 失败。

修法:把 workspace 统一到单一 zod 版本——`apps/web` 与 `apps/mcp` 的 zod spec 同时对齐到 `^4.4.3`
(SDK 本就要 4.4.3,hookform@5.2.2 也偏好 minor 4)。`@tanstack/router-*` 的 zod v3 仍各自嵌套、不受影响。
顶层 + web + mcp + SDK 现统一为 `zod@4.4.3`,`bun install --frozen-lockfile` 自洽通过。

> 注:务必用 `bun install`(或 `--frozen-lockfile`)而非裸装乱序;新增 workspace 包会重组 vitest 树(因 mcp 也是 vitest 消费者),属正常 hoist 重排。

## Phase 4 评审与修复

独立上下文双评审(code-reviewer + security-reviewer)结论均为 **可合并 / LOW 风险**,无 blocker/high/medium。
读到的 LOW 项已就地修复并复验:

- 删除未使用的 `@ttpos/shared` 依赖(声明却未 import)。
- `get_telemetry` 的 `date` 入参加 `^\d{4}-\d{2}-\d{2}$` 正则约束(非法 date 由 SDK 校验拒绝,冒烟已验证)。
- 上游 **5xx** 错误体不再原样透传给 agent:归一为 `Upstream error (status N)`,细节只进 stderr(防内部信息泄露)。
- `config.ts`:用户名/密码只给一半时 stderr 告警,不再静默降级为匿名。
- 补两个鉴权负路径单测:token 模式 401 不触发登录重试;login 模式连续 401 一次刷新后终止(不递归)。
- README 增加「使用只读作用域凭据」运维提示。

复验:`typecheck` 全 0、`lint` 0、`test` **mcp 28 / web 39**、`bun install --frozen-lockfile` no changes、stdio 冒烟(含 date 校验)通过。

评审确认的正向点:只读边界由 `RegistryApi` 接口在结构上保证(工具层只见 `get`,写动词不可达);stdout 纯净(仅 `console.error` 走 stderr);凭据不进 stdout/工具响应;query 经 `URLSearchParams` 编码、路径为字面量(无 SSRF);`redirect:'manual'` 不跟随重定向;两处外呼均带 `AbortSignal.timeout`。
